01 / Commands

What it did, what leaked, what it may do next.

ranwhat is an open-source command-line tool for AI coding agent security. It reads what Claude Code and eleven other coding agents have already written to disk: what they ran, and which credentials leaked into their history. scan adds what their tokens still allow. Only clean changes your files, and only when you ask it to.

ranwhat check

Runs watch and clean in one read-only pass: what your agents ran, and what they left on disk. It never changes anything.

03 / Questions

AI agent security, in plain terms.

What is AI agent security, and how is it different from LLM security?

LLM security is about the model and what it says: jailbreaks, harmful output, leaked training data. AI agent security is about what an agent does once it has tools and credentials: the commands it runs, the files it reads, the tokens it uses. Prompt injection is how an attacker steers it. ranwhat covers the agent side, on your own machine and after the fact. It does not detect prompt injection or block anything while the agent works. The AI coding agent security checklist covers the parts it does not.

Can an AI coding agent leak my API keys?

Yes, in two ways. It can write a key into code it commits, which is what repository secret scanners look for. And when a command it runs prints a key, through cat .env, env or a config file, the output is saved in its transcript in plaintext and sent to the model as context. Repository scanners do not look there. ranwhat clean finds those copies and tells you what to rotate.

What should I do if an AI agent exposed my API key?

Rotate it at the provider first: create the replacement, revoke the old key, then check the provider's logs for use you do not recognise. Deleting or masking the transcript does not undo the leak, because the value has already been on disk and in a model context. Masking only stops those copies leaking again. ranwhat clean leads with what to rotate and where, and masks the copies on disk when you ask.

How do I audit what an AI agent did on my machine?

Read back the history it already wrote. Most coding agents record each tool call they make, with its output, and that record is an audit trail you can search. ranwhat watch runs nine rules over it: credential reads, rm -rf, force pushes, npm publish and more. History expires, Claude Code's after 30 days by default, so for a record from now on add a hook or OpenTelemetry, as the audit log guide shows.

What does least privilege mean for an AI agent's tokens?

The agent gets its own token, with only the scopes its task needs and an expiry date, rather than your own admin key. A permission prompt decides which command runs; the token decides what that command can do once it reaches GitHub, Stripe or AWS. ranwhat scan scores what an agent's tokens allow, read-only, from a catalogue of 104 scopes across twelve providers, and --pull-usage shows which grants were never used, where the provider keeps a record.

What does OPSEC mean for a developer who uses AI agents?

OPSEC, operations security, is keeping information an adversary could use out of their reach. On a developer's laptop that information is mostly credentials: shell history, .env files, keys in ~/.aws and ~/.ssh, and now agent transcripts, which keep tool output in plaintext in your home folder. Anything that can read your files can read those, malware included. In practice: know what is there, rotate what leaked, and keep secrets out of the agent's reach.
