FAQ

Questions about ranwhat

What it reads, what it sends, what it changes, and where it fits in AI coding agent security.

Questions

The ones worth answering up front.

Does it send anything anywhere?

Not unless you ask it to. check, watch, clean, scan and demo read files on disk and print to your terminal. live and --pull-usage ask only the provider that issued each token. update fetches the capability catalogue for Plus subscribers and sends only the subscription token. There is no telemetry and no account.

Does it need my credentials?

The watcher needs none at all. Point it at your machine and it works. The authority scanner can introspect tokens read-only, but it never exercises a permission and never needs a write-scoped credential. Pass tokens through the environment rather than the command line, because anything in argv is readable by every user on the machine.

Which agents does it read?

Claude Code, Codex, Gemini CLI, GitHub Copilot CLI, Qwen Code, Grok Build, Droid, Kimi Code, Kimi CLI, Pi, Muse Code and OpenClaw, from the history each writes to disk. check, watch and clean read all twelve by default, and ranwhat sources says where it looked for each. OpenClaw keeps its history in a database, so clean finds its secrets but only reads them. Meta Muse, Grok Bot and the current Amp keep theirs in their vendor's cloud, so there is nothing on your machine to read. Cursor is next. It reads files the agent already wrote, so there is no wrapper, no proxy and nothing in your critical path.

Does it read everything Claude Code writes?

Not yet. It reads the session transcripts, ~/.claude/projects/*/*.jsonl, and the transcripts their subagents write, for the last 30 days by default. The large tool outputs Claude Code stores in separate files, and ~/.claude/history.jsonl, are not read yet. If CLAUDE_CONFIG_DIR is set, it reads $CLAUDE_CONFIG_DIR/projects instead, and --root PATH points it at any other directory. A run that reads nothing says that nothing was checked, rather than that nothing was found. The Claude Code history guide lists what each of those files holds and how long it stays.

Will it slow my agent down?

No. It runs after the fact against files on disk. Your agent never knows it exists.

Is it safe to run clean --apply?

It reports by default and changes nothing until you ask. When you do, it writes a timestamped backup first, then parses the rewritten file back before replacing the original, so a transcript is never left corrupted. Ordinary config, templates and placeholders are left alone.

If I mask a secret, is it safe now?

No, and the tool says so. The value was already written to disk in plaintext and already sat in a model context you do not control. Masking stops it leaking a second time. Rotating it is the actual fix, which is why the report leads with what to rotate and where.

How is this different from scanning my agent's config?

Tools that scan agent components look for known-bad content in what is installed: MCP servers, skills, configuration. ranwhat looks at what your agent actually did with the access it has, and what it is still allowed to do next time.

Is ranwhat a security tool for Claude Code?

It covers one part of AI coding agent security: what Claude Code and other coding agents already ran, the secrets they left in their transcripts, and what an agent's credentials still allow. It does not block anything while the agent works. For that, Claude Code has permission rules, hooks and a sandbox.

What does it cost?

Nothing on your own machine, forever, and the code is MIT licensed with no dependencies. Paid tiers, being built now, are for collecting records across machines and for evidence retention. We never charge per finding, because a tool paid by the alert has a reason to cry wolf.

Does it work on Linux and Windows?

Linux and macOS, yes. Windows is untested. It is pure Python with no dependencies, so it will probably work, but nobody has verified it. Tell us if you do.
